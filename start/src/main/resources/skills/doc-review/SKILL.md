# 文档审查

## When to Use

审查文档质量、核对文档与代码是否一致、文档评审或改动代码后确认相关文档是否需要同步更新。

## 审查维度

1. **结构完整性**：标题层级清晰、章节齐全（背景/方案/示例/注意事项/参考）、无空章节
2. **技术准确性**：代码示例与实现一致、配置项/字段名/接口路径真实存在、命令可直接执行
3. **一致性（三处同步约定）**：功能改动后，README、`mwb-ai-claw技术方案.md`、`docs/` 相关 feature 文档是否同步——核查：
   - 新能力/新配置是否在 README 与主技术方案中体现
   - docs 方案文档状态（WIP/PENDING/SUBMIT/Deprecated）与实施进度是否匹配
   - 引用的类名/文件路径/编排 id/技能名是否存在
4. **格式规范**：表格对齐、代码块标注语言、术语统一
5. **图可渲染**：所有 mermaid 块语法正确（配合 markdown-diagramming 规范；classDiagram 注意 v10 兼容性）

## 输出格式

```markdown
## 审查结论
总体评价（可用/需修订）+ 问题数

## 问题清单
- **[严重]** 位置：错误内容 | 正确内容/建议
- **[中等]** ...
- **[提示]** ...
```

## 要点

- 严重级别：[严重] 技术错误或文档-代码不一致会误导；[中等] 明显遗漏；[提示] 格式/措辞
- 核对代码时用 grep/read 验证引用的类、配置、路径是否真实存在
- 修订后建议复查一次差异部分，形成闭环
