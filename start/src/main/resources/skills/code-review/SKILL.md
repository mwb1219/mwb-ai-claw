# 代码审查

## When to Use

用户要求审查改动、评估代码质量、找 Bug / 安全隐患 / 性能问题，或提交前自查。

## 工作流

按以下维度逐项审查，每项给出「严重级别 + 位置 + 问题 + 建议」：

1. **正确性**：边界条件（null/空/越界）、并发安全（共享状态/竞态）、异常处理路径是否完整
2. **安全**：注入（SQL/命令/路径穿越）、敏感信息泄露（日志/硬编码密钥）、权限校验、输入校验
3. **性能**：N+1 查询、循环内 IO、大对象复制、无界缓存/线程池、热路径日志
4. **可维护性**：命名、重复代码、圈复杂度、注释与代码一致性、死代码
5. **规范**：项目约定（分层职责、DTO/领域对象边界、事务边界、错误码使用）

## 输出格式

```markdown
## 审查结论
总体评价（可用/需修改）+ 关键问题数

## 问题清单
- **[严重]** `文件:行` 描述 | 建议
- **[中等]** ...
- **[提示]** ...
```

## 要点

- 严重级别：[严重] 会出错/有安全风险；[中等] 明显缺陷；[提示] 改进建议
- 先看调用链和上下文再下结论，避免误报；无法确定时标注「需确认」
- 审查后可建议用 write_memory 记录跨会话的常见问题模式
