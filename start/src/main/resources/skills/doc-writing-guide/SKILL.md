# 文档写作规范

## When to Use

撰写或改写任何 Markdown 文档；与其他文档类技能（tech-design-doc / api-documentation / readme-writing）叠加，作为写作风格基座。

## Markdown 结构规范

1. **标题层级**：`#` 文档标题 → `##` 章节 → `###` 小节 → `####` 细项；不跳级、不用标题加粗代替
2. **表格**：表头 + 分隔行（`|------|`）；列少而语义明确用表格，否则用列表
3. **代码块**：标注语言（```java / ```bash / ```yaml / ```json / ```mermaid）；行内代码用反引号
4. **引用块**：`>` 用于状态说明、注意事项、约定声明
5. **列表**：同级列表符号一致；嵌套缩进两空格
6. **图**：mermaid 块（` ```mermaid `）替代 ASCII 图；图前有引导语、图后有要点说明

## 中文写作原则

- **简洁**：一句话能说清的不用两句；删掉「众所周知」「值得注意的是」等空话
- **术语一致**：全文档同一概念用同一译名（如「编排」不混用「Orchestration」）；首现可括注英文
- **主动语态**：优先「选择器执行 X」而非「X 被执行」
- **以读者为先**：先结论后细节（金字塔式）；长文档先给目录/摘要
- **数字与单位**：代码里的数字用代码块原样，叙述性数字用中文

## 通用文档模板

```markdown
# 文档标题
> 状态/版本/日期 | 适用范围

## 背景与目标        # 为什么写、解决什么
## 说明 / 方案       # 主体内容
## 示例             # 代码/配置示例
## 注意事项         # 边界、坑、约定
## 参考             # 相关文档/链接
```

## 要点

- 先确认目标读者与文档类型再动笔（README vs 内部方案 vs 接口文档结构不同）
- 写完自检：标题层级是否清晰、表格是否对齐、mermaid 图是否可渲染（配合 markdown-diagramming）
