# 数据库设计

## When to Use

用户要求设计表结构、评估现有表设计、写建表 SQL，或排查索引/查询性能问题。

## 设计规范

1. **命名**：表名单数下划线（`user_account`）；字段 `snake_case`；主键 `id`（BIGINT/雪花）；逻辑删除 `deleted`；审计字段 `created_at / updated_at / created_by / updated_by`
2. **主键与唯一约束**：每表必有主键；业务唯一性用唯一索引（如 `uk_user_mobile`），不依赖应用层
3. **索引**：查询条件/排序字段建索引；联合索引按最左前缀；避免索引列上做函数运算；索引覆盖高频查询可省回表
4. **外键**：生产库不建物理外键（影响写入性能与分库），用应用层保证一致性
5. **范式与反范式**：默认 3NF；高频冗余读场景允许适度反范式（冗余字段 + 更新维护）；大字段（text/blob/json）拆出或单独表
6. **类型选择**：金额用 DECIMAL(18,2) 或分单位 BIGINT；枚举小数值用 TINYINT + 字典表/注释；时间用 DATETIME/TIMESTAMP 统一时区

## 输出格式

为每张表输出：用途说明 + 字段清单（列名/类型/约束/说明）+ 索引清单 + 建表 DDL（含注释）。

## 要点

- 先问清查询场景（读多写少/写多读少）再定索引
- 涉及现有表时，先读原 DDL/实体类，避免与代码不一致
- 可用 write_memory 记录设计决策供后续会话复用
