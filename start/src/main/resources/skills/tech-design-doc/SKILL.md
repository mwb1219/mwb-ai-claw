# 技术方案编写

## When to Use

用户要求为功能 / 改造编写技术方案，或把想法整理成可评审的文档。

## 文档结构（docs/ 目录，命名 feature-xxx技术方案(状态).md）

```markdown
> 状态：WIP（待实施）/ SUBMIT（已实施）| 日期
> 涉及模块 / 优先级

## 1. 背景与目标
## 2. 术语与相关文档
## 3. 需求分析
## 4. 总体方案（含架构图）
## 5. 详细设计（模块/数据模型）
## 6. 与现有能力的兼容性
## 7. 实施步骤（有序、可验证）
## 8. 测试计划
## 9. 风险评估
```

## 要点

- **图优先用 mermaid**：架构用 flowchart、状态用 stateDiagram-v2、时序用 sequenceDiagram、类模型用 classDiagram；避免旧版不兼容语法（如 `class X <<注解>> {`，用 `%%` 注释 + 分离写法）
- **实施步骤可验证**：每步给出可运行验证方式（编译/启动日志/接口调用）
- **变更影响清单**：列出需要同步的文档（README、技术方案主文档、docs 目录）
- **图渲染验证**：写完后用支持 mermaid 的工具确认语法（可在技术方案主文档用 render 脚本双版本验证）
- 控制篇幅：背景简要、设计详尽、避免复制代码贴文档
